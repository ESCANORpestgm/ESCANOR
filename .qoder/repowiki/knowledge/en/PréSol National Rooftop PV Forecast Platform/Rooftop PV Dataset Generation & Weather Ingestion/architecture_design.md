Two cooperating sub-packages form the data supply layer for the forecasting pipeline. `data/` holds dataset generators (`generate_rooftop_dataset.py`, `generate_pvgis_rooftop_data.py`, `generate_continuous_rooftop_data.py`) plus the authoritative reference catalog `steg_districts.py` (50 STEG commercial districts across 7 Directions de Distribution, with capacity, coordinates, dust loss, tilt/azimuth) and a compatibility shim `governorates.py` that re-exports it under legacy names. The generators each produce a DataFrame conforming to a fixed column set (`timestamp_utc`, `location_id`, `district`, `direction`, `pv_count`, `installed_capacity_kwp`, `tilt_deg`, `azimuth_deg`, irradiance columns, `power_kw`, `energy_kwh`, `horizon_hours`, cyclic time features, `source`, `dataset_version`). `ingestion/` provides the external-data adapters: `weather_client.py` fetches real Open-Meteo forecasts concurrently via `httpx.AsyncClient` + `asyncio.gather` across all governorates/districts and builds a live weather DataFrame; `pvgis_client.py` queries the JRC PVGIS seriescalc API per district with JSON file caching; `synthetic_data.py` generates offline-reproducible weather and PV output using a single-diode-inspired model with horizon-dependent noise buckets. Dependency direction is one-way: `data/*` imports from `ingestion.*` (and never the reverse), so the ingestion layer is the only place network calls occur. Raw Prosol report text lives in `data/source/` as reference material.

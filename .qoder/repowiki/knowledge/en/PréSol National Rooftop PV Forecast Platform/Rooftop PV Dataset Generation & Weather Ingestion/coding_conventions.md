- Each generator exposes a pure function returning a pandas DataFrame plus an `argparse`-based `main()` guarded by `if __name__ == "__main__"`, enabling both programmatic import and CLI execution.
- Output DataFrames are built around a shared column contract (`timestamp_utc`, `location_id`, `district`, `direction`, `pv_count`, `installed_capacity_kwp`, `tilt_deg`, `azimuth_deg`, irradiance fields, `power_kw`, `energy_kwh`, `horizon_hours`, cyclic sin/cos time features, `quality_status`, `source`, `dataset_version`) so downstream ML code consumes a uniform schema regardless of data source.
- Cyclic temporal features are derived by converting timestamps to hour-of-day and day-of-year then computing `sin(2π·t/T)` and `cos(2π·t/T)` pairs inside a local `_cyclic_features` helper.
- External API responses are wrapped with explicit error raising (`requests.HTTPError`, `ValueError` on missing keys) and, for PVGIS, cached to a JSON file keyed by district name and year range before parsing.
- District/governorate entities are duck-typed: ingestion functions accept any object exposing `.name`, `.lat`, `.lon`, and optionally `.direction`/`.district`, allowing both `StegDistrict` and legacy `Governorate` objects to be passed interchangeably.
- Synthetic randomness is seeded via `np.random.default_rng(seed)` at the top of each run (default seed 42) and exposed through module-level `RNG` so generated datasets are reproducible.

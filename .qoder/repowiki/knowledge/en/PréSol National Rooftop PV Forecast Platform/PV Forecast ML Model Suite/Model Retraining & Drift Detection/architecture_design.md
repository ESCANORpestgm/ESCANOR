Three cooperating entry points form the retraining workflow. `retrain.py` is the core engine: `check_drift_and_retrain` loads current models, computes MAE on recent data, builds a persistence baseline (last known production per governorate), and triggers retraining only when the model's MAE is within DRIFT_THRESHOLD_PCT of persistence. On trigger it creates an immutable training run via `model_registry`, trains candidate quantile models with `train_quantile_models`, evaluates them on a hold-out validation split, registers the candidate, and attempts promotion to the active model path (`artifacts/quantile_models.joblib`). `retrain_historical.py` is a CLI wrapper that reads validated rooftop CSVs from `results/datasets`, adapts them into the canonical schema via `rooftop_training_adapter.build_training_frame`, runs the same drift check, and appends results to a `RETRAIN_LOG`. `rooftop_training_adapter.py` is a pure data-shaping layer that validates required columns, filters by quality status, aggregates power by district/direction, normalizes timestamps and units (kw→mw), and merges weather features (either embedded in the measurement file or supplied as a separate CSV). Dependency direction is one-way: both CLI scripts depend on the core retrain logic and the adapter; the core depends only on `ml_forecast`, `model_registry`, and `data.steg_districts` — no reverse imports.

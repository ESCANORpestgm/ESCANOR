The module is split into four cooperating layers: (1) `ml_forecast.py` defines the shared feature pipeline (`add_time_features`) and trains/evaluates three LightGBM quantile regressors (P10/P50/P90) on per-district data; (2) `aggregation.py` rolls district forecasts up to direction/national levels using sqrt-sum-of-squares uncertainty combination; (3) `model_registry.py` provides an immutable JSON-backed registry under `results/model_registry/` for training runs, model versions, and the current production artifact, enforcing promotion only when a candidate's MAE beats production; (4) `retrain.py`, `retrain_historical.py`, `rooftop_training_adapter.py`, `validation_report.py`, and `history.py` orchestrate scheduled retraining, historical backfills, rooftop-specific adapters, and drift detection against a persistence baseline. Training scripts call `ml_forecast.train_quantile_models` → `evaluate` → `model_registry.register_model` → `promote_model`, while inference callers load artifacts via `joblib.load` from `models/artifacts/`. The whole suite depends on the shared schema of `timestamp`, weather features, governorate/district identifiers, and `production_mw` targets.

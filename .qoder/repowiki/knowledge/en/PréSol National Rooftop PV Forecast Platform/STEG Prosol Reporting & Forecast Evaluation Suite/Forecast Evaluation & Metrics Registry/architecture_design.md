Three cooperating modules form a pipeline from data to discoverable results:
- `forecast_evaluator.py` is the core engine: it validates CSV schemas (kW-only, required columns), merges forecast and actual data on `(location_id, timestamp)`, computes per-row errors/coverage/interval width, groups metrics by location, horizon bucket (`nowcast_0_1h`, `short_term_1_6h`, `day_ahead_6_24h`, `extended_24h_plus`), and optional geographic dimensions, then writes an immutable run directory containing `evaluated_values.csv`, `summary.json`, and optionally `run_metadata.json`. It also exposes `save_forecast_snapshot` for persisting raw forecast runs under `results/forecast_runs/<run_id>`.
- `historical_evaluation.py` is a CLI entry point that loads historical rooftop data, runs the ML model via `models.ml_forecast.predict`, converts MW predictions to kW, and delegates to `evaluate_forecast`, writing a `historical_metadata.json` alongside the summary.
- `evaluation_registry.py` is read-only: it scans `results/forecast_evaluations` and `evaluations` for `summary.json` files (and sibling `historical_metadata.json`), sorts by mtime, and exposes `list_evaluations()` / `get_evaluation()` used by the API/dashboard.
Dependency direction is one-way: `historical_evaluation` → `forecast_evaluator`; `evaluation_registry` depends only on filesystem layout. All outputs are append-only directories keyed by a generated `evaluation_id` or `run_id`.

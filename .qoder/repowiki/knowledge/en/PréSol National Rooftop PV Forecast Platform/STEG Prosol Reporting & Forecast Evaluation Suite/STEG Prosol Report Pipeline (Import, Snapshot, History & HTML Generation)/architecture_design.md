The module is organized as a linear data pipeline with clear separation of concerns across five files:
- `prosol_report_importer.py` parses a `pdftotext -layout` output of the official STEG Prosol dashboard, extracts national metrics, direction/district breakdowns, pending dossiers and installation sizes via regex-based section slicing (`section()`, `numeric_tail()`), validates totals against hard-coded expected national figures, and writes a normalized JSON snapshot plus an optional CSV export and a `report_registry.json` manifest.
- `prosol_history_db.py` provides immutable persistence for those snapshots: a SQLite schema (`prosol_reports`, `prosol_national_metrics`, `prosol_directions`, `prosol_districts`, `prosol_installation_sizes`, `prosol_pending_dossiers`) keyed by a SHA-256-derived `snapshot_id`, with `import_snapshot`, `import_generated_snapshots`, `list_reports`, and `get_report` APIs.
- `prosol_updates.py` implements an append-only log at `results/prosol_updates/installation_updates.jsonl` (validated per-district via `DISTRICT_BY_NAME` and `AVG_UNIT_KWC`), exposing `add_installation_update`, `list_installation_updates`, and `aggregate_updates`.
- `prosol_report_generator.py` composes the final report: it loads an imported snapshot via `_load_imported_summary`, overlays live updates through `_apply_live_installation_updates` (mutating indicator rows 1–2 and the completion rate), falls back to embedded static values when no snapshot exists, and renders a styled A4 HTML document via `generate_html_prosol_report`. It also depends on `data.steg_districts` for district metadata and national totals.
- `prosol_installation_export.py` derives flat district-level new-installation rows from a snapshot for downstream CSV consumption.
Dependency direction is one-way: importer → history DB; generator reads from both history DB (via snapshot path) and the live-updates log; exporter consumes snapshots only. No cross-imports between the five files except `prosol_report_generator` → `prosol_updates`.
